# Coastline Inbox Zero runtime

The single Azure-hosted Coastline runtime is enabled with
`COASTLINE_DRAFT_PROPOSALS_ENABLED=true`. Registered capabilities may draft,
organize, file attachments, unsubscribe through verified HTTPS links, create
calendar events, and create Teams actions. They execute through their existing
provider-boundary policy and receipt paths without per-item approval or volume
limits.

`NEXT_PUBLIC_EMAIL_SEND_ENABLED=false` is permanent for this deployment.
`Mail.Send` is not requested. Coastline rejects send, reply, forward, trash,
and non-owned draft deletion at the provider boundary. Resend and notification
email paths are also suppressed while the Coastline runtime flag is enabled.

The Outlook draft renderer writes deterministic Verdana 10pt HTML. Signature
color is derived from a sent-message signature when available and recorded with
its source ID and hash. A retained color is marked `last_known`; an absent
signature is marked `configured_default`, never verified evidence.

## One-time canary

Before the first live use, run one dedicated canary mailbox through the Azure
runtime. Record the deployed artifact identifier, exact target, idempotency
replay, provider readback, and correction path in the existing receipt store.
This is a one-time proof exercise, not an ongoing reviewer or SHA approval
gate. Do not claim this canary or a production deployment occurred without its
external receipt.

Keep runtime values out of Git. The deployment requires its database,
authentication, Microsoft OAuth, queue, and cron settings; it also sets:

```text
COASTLINE_DRAFT_PROPOSALS_ENABLED=true
NEXT_PUBLIC_EMAIL_SEND_ENABLED=false
```

Use `COASTLINE_DRAFT_PROPOSALS_ENABLED=false` as the emergency kill switch.
It disables Coastline registered automation while leaving the application
itself available for investigation and recovery.

## Local validation

Local tests and builds never contact Microsoft 365. Run focused Vitest tests,
TypeScript checks, and `git diff --check` before deployment. A local pass is
diagnostic evidence only; the one-time Azure canary receipt is the proof of a
live provider write and readback.
